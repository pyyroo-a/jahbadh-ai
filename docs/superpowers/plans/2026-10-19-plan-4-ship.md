# Jahbadh Plan 4: Ship It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the working local desk into the submission. That means honest Referee numbers from an eval with planted false claims, a layout made for each persona and for phones, outside events driving the desk through an ingest API, and a keyless, traced deployment on Azure Container Apps that judges can open until 10 Nov. It also covers CI, the README, the video script and the submission text.

**Architecture:**
- **Eval:** a planting seam in the agent pipeline puts known-false claims into real writer drafts. The Referee checks them like any draft, and they are then dropped and counted.
- **New data, worked out on the server:** pass speed (synthetic, like shot speed), a per-player table and shot counts. The browser keeps drawing only what the server sends.
- **Persona layouts:** the persona picks one of three layouts (Fan, Analyst, Player watch), each with a phone version under 768 px.
- **Ingest:** an `IngestRun` plays events as they are posted, with the same stream protocol as live mode.
- **Azure:** the app ships as one container. Bicep (run with azd) puts the app in its own resource group and points at the existing Foundry and Translator resources.

**Tech Stack:**
- **Python:** Python 3.13, FastAPI, Agent Framework 1.22 on Foundry gpt-5-mini.
- **New runtime deps:** `azure-identity`, `azure-monitor-opentelemetry` and `httpx2`.
- **Eval extra:** `azure-ai-evaluation`.
- **Web:** React 19, Vite 8, Vitest 5.
- **Azure:** Container Apps (consumption), Container Registry Basic, Azure Files, Log Analytics and Application Insights, a user-assigned managed identity, Bicep with the Azure Developer CLI.
- **CI and deploy:** GitHub Actions with a federated credential.

**Spec:** `docs/superpowers/specs/2026-10-19-plan-4-ship-design.md` (this plan argues from it). It builds on `docs/superpowers/specs/2026-10-17-jahbadh-design.md` and Plan 3 (`docs/superpowers/plans/2026-10-18-plan-3-desk.md`). The approved mockups are in `.superpowers/brainstorm/864-1792429037/content/` (gitignored): `phone-and-analyst.html` and `fantasy-view.html`.

### Task 3: The eval harness (free, scripted)

**Files:**
- Modify: `src/jahbadh/agents/desk.py` (`Desk` gains `planter`), `src/jahbadh/agents/pipeline.py` (WriterStep about :74, RefereeStep :84-93)
- Create: `src/jahbadh/eval/__init__.py`, `src/jahbadh/eval/plant.py`, `src/jahbadh/eval/harness.py`, `src/jahbadh/eval/report.py`, `src/jahbadh/eval/__main__.py`
- Test: `tests/eval/evalfakes.py` (loads `tests/agents/fakes.py` by path, like `apifakes.py`), `tests/eval/test_eval_plant.py`, `tests/eval/test_eval_pipeline.py`, `tests/eval/test_eval_report.py`

**Interfaces:**
- `jahbadh.eval.plant`:
  - `PlantKind = Literal["wrong_number", "wrong_player", "made_up_event", "wrong_team", "wrong_minute"]`, `PLANT_KINDS: tuple[PlantKind, ...]` in that order.
  - `class PlantResult(BaseModel): seed: int; moment_id: str; claim_id: str; kind: PlantKind; source_claim_id: str | None; text: str; caught: bool; layer: str | None; reasons: list[str]`
  - `plant_claim(kind: PlantKind, claims: list[Claim], match: Match, moment: Moment, rng: np.random.Generator, n: int) -> Claim | None`. It gives id `f"{moment.id}:p{n}"`, and `None` when no draft claim suits the kind. The kinds:
    - `wrong_number`: one figure's `written` value changes in the text and the figure. A percentage moves by 15 points, a decimal is multiplied by 1.5 at the same decimals, a whole number gets +2.
    - `wrong_player`: a named player in the text becomes a player from the other team.
    - `made_up_event`: a new sentence "{player} hit the post at {minute}'." citing one real PASS by that player in the moment's window.
    - `wrong_team`: the one club name in the text is swapped for the other club.
    - `wrong_minute`: a `{n}'` minute in the text moves 20 minutes away (staying within 1 to 90).
  - `class Planter`: `Planter(seed: int, schedule: dict[str, PlantKind])`, keyed by moment id. Its calls:
    - `__call__(run: MomentRun, drafts: list[Claim]) -> list[Claim]`
    - `record(claim: Claim, rejection: Rejection | None) -> None`
    - `results: list[PlantResult]`
    - `is_planted(claim_id: str) -> bool`, which matches `":p"` ids it made.
  - `schedule_plants(moments_by_seed: dict[int, list[Moment]], total: int = 50) -> dict[int, dict[str, PlantKind]]`. Kinds go round-robin in `PLANT_KINDS` order, and matches take turns, so each kind gets `total // 5`. Moments are picked evenly through each match. `full_time` and spotlights are skipped.
- `Desk.planter: Planter | None = None`.
  - **WriterStep**, attempt 0 only: `s.pending += desk.planter(run, s.pending)`.
  - **RefereeStep:** planted claims go through `referee()` with the rest. Then, for each planted claim, it calls `planter.record(claim, its first rejection or None)` and removes it from `approved`, `retry`, `stats["drafted"]` and `stats["passed_first"]`. So a planted claim is never rewritten, published or counted in the first-draft stats.
- `jahbadh.eval.harness`:
  - `class EvalReport(BaseModel)`, with fields:
    - `seeds: list[int]; model: str; created: str; moments: int; failures: int`
    - `first_draft: dict[str, int]` (`passed`, `drafted`)
    - `rejections_by_layer: dict[str, int]`
    - `plants: list[PlantResult]`
    - `numbers: dict[str, int]` (`checked`, `matching`)
    - `latency_s: dict[str, float]` (`mean`, `p50`, `p90`, `max`)
    - `tokens: dict[str, int] | None`
    - `showcase: dict[str, object] | None`
  - `async run_eval(seeds: list[int], desk_factory: Callable[[Match, Planter], Desk], total_plants: int = 50, concurrency: int = 3) -> EvalReport`. For each seed it runs `simulate_match(seed)` (no storyline), `jahbadh.api.live.key_moments(match)`, then `run_desk`.
    - `numbers` re-runs layer 1 (`grounding.check_claim`) on every published claim's figures.
    - `latency_s` comes from `FeedItem.latency_s`.
  - `recheck_showcase(show: Showcase) -> dict[str, object]`. It returns `{"published": int, "would_fail": int, "failing": [[claim_id, reasons], ...]}` using today's layer 1, free.
- `jahbadh.eval.report`: `catch_summary(report) -> dict` (`caught`, `total`, `by_kind`, `by_layer`) and `to_markdown(report: EvalReport) -> str`.
- CLI:
  - `python -m jahbadh.eval --seeds 1-20 --plants 50 --out data/eval/<name>` writes `report.json` and `report.md`.
  - `--dry` prints matches, key moments and planned plants without any model call.
  - `--limit-matches N` runs only the first N seeds.
  - `python -m jahbadh.eval showcase` prints the recheck.
